## 冒頭に置く前提

このリポジトリでは **Notion が正本、`docs/` は写し**。
ローカルの `docs/` への追記は暫定記録であり、**Notion へ反映して初めて正本になる**。このスキルはその反映を漏れなく行うためのもの。

## 実行順序（この順を厳守）

```javascript
① 今セッションの棚卸し
② docs/DECISION_LOG.md 更新（設計判断があった場合のみ）
③ docs/SESSION_STATE.md 更新（毎回）
④ git commit
⑤ Notion へ反映
⑥ 検証
```

④を⑤より先に置く理由：git は戻せるが Notion の書き戻しは戻しにくい。途中で失敗しても手元に成果が残る状態を作る。

## ① 今セッションの棚卸し

作業ログを遡り、次を分類する。ユーザーに聞く前に自分で分類すること。

- **設計判断**（仕様・方針を決めた／却下した）→ ②へ
- **実装のみ**（既定の仕様どおりに作った）→ ②はスキップ、③のみ
- **未解決のまま終わる論点** → ③の「未確定項目」へ

判断に迷ったら「この決定を半年後の自分が知らなかったら困るか」で判定する。困るなら設計判断。

## ② DECISION_LOG.md 更新

既存フォーマットに合わせて追記する。**追記位置（冒頭か末尾か）はファイル側の規約に従う。** ファイルに明記がなければ既存エントリの並び順から判断する。日付は実際の日付を確認して使う。
項目：`# YYYY-MM-DD｜<決定を1行で>` の見出しの下に、**決定** ／ **理由** ／ **却下した案** ／ **根拠・参考** の4つ。
★ **「却下した案」を空欄にしないこと。**
却下案と理由を残すのがこのログの主目的。将来のAIが同じ案を再提案するのを防ぐため。却下案が本当に無かった場合のみ「なし（対立案が出なかった）」と明記する。

## ③ SESSION_STATE.md 更新

3項目を必ず埋める。前回の内容を消さず、現在の状態に**上書き更新**する。

- **現在の進捗**：何がどこまで動いているか
- **次にやること**：次のセッションの最初の一手。曖昧な表現にしない
- **未確定項目**：判断待ちで止まっているもの

冒頭に更新日を書く。日付は推測せず確認する。

## ④ git commit

`git add -A` → `git status` で意図しないファイルが混ざっていないか確認 → `git commit`。
コミットメッセージは実際の変更内容と一致させる。「更新」「修正」だけの内容のないメッセージにしない。

## ⑤ Notion へ反映

対象ページの ID は `CLAUDE.md` の「Notion ページID」節を参照する。
記載がなければ**そこで停止し、ユーザーに ID を尋ねる**（検索で当てにいかない）。
★ 同名ページの取り違えが実際に起きている（2026-07-26、遠征の作業中に「DECISION_LOG」で検索して天使様配下のページがヒットした）。

- 追記は `insert_content` を `position: end` で
- 既存記述の書き換えは `update_content` の `old_str` / `new_str` で外科的に
- **ページ全体を置換しない**
- Notion の既存記述と今回の決定が矛盾する場合、**上書きせず停止**する

## ⑥ 検証

以下を自分で確認し、1行ずつ報告する。どれか1つでも通らなければ、報告せず修正してから再確認する。

- DECISION_LOG に追記したエントリの「却下した案」が空でない
- SESSION_STATE の3項目がすべて埋まっている
- SESSION_STATE の更新日が今日の日付
- `git log -1` で意図したコミットが積まれている
- **Notion 側を `notion-fetch` で読み直し、追記内容が実在する**
- Notion とローカルの記述が矛盾していない

★ 「書き込み成功」の応答を信用しないこと。2026-07-26、複数箇所の置換で成功と返ったが1箇所しか当たっていなかった実例あり。**必ず読み直す。**

最後に、次のセッションで最初にやることを1行で示して終わる。

# 停止条件

以下に当たったら、作業を止めてユーザーに判断を仰ぐ。勝手に決めて記録すると、誤った内容が正本に入る。

1. 今回の決定が Notion の既存記述と矛盾する
2. 今回の決定が DECISION_LOG で既に却下済みの案に該当する
3. 設計判断かどうかの分類がつかない
4. Notion のどのページに書くべきか判断がつかない
5. コミット対象に意図しないファイルが含まれている

## 停止時に出力する形式

「止まりました」だけでは判断できない。必ず次の4点を出す。

```javascript
【論点】<何を決める必要があるか・1行>

【選択肢】
A: <案>
B: <案>

【トレードオフ】
A: 得られるもの / 失うもの
B: 得られるもの / 失うもの

【却下済みか】
DECISION_LOG を確認した結果：<既出の有無。既出ならその日付と理由>

→ A / B どちらにしますか
```

★ 最後は **A/B の一問一答で答えられる形**まで畳むこと。ユーザーは移動中に音声で返答することがある。

# やらないこと

- ユーザーに確認せずに新しい仕様を決める
- 却下済みの案を「改善案」として再提案する
- Notion のページを丸ごと書き換える
- 記録を省略して「完了しました」とだけ返す
