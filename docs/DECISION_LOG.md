# 2026-07-13｜販売方針：R-18版のみを制作する

**決定**
R-18版のみを制作し、DLsite先行で出す。全年齢版は当面作らない。Steamは対象外。

**理由**
- 昼のチルさと夜のギャップが商品の本体であり、夜のパートを外すと作品が成立しない
- 2025年7月以降、Steamは決済代行業者・カード会社の基準を理由に成人向けゲームの削除を継続している。Valve自身が「決済手段を失うと他タイトルも購入できなくなるため」と説明
- 2026年4月には、成人向けゲームの売上送金が国内銀行に停止された事例も報じられている

**却下した案**
- **全年齢版を先に完成させ、後からR-18版を作る**：却下。作品の核が夜のギャップにあるため、全年齢版は「本体を欠いた版」になる。制作リソースも二重にかかる
- **Steamで成人向けとして配信**：却下。決済リスクが高すぎる

**未解決の依存**
- DLsiteも2024年からクレカ問題の影響下にある。販路を1本に依存せず、Fanza・BOOTH等も視野に入れる

# 2026-07-13｜全年齢/R-18 差し替えアーキテクチャの位置づけを変更

**決定**
差し替えアーキテクチャ（`text_normal` / `text_adult`、AssetResolver、モード切替）は**実装済みのまま維持するが、当面は r18 モード固定で運用する**。

**理由**
- 実装コストは既に支払い済み。削除する方が手間がかかる
- 将来的に全年齢版を出す判断をした場合、スキーマを後から足すのは全シーンデータの手直しになり高コスト

**却下した案**
- **差し替え機構を削除して単純化する**：却下。将来の可逆性を失う割に、得られる単純さが小さい

# 2026-07-13｜キャラクター記号の確定

**決定**
- シスター服ベース。**既存の宗教モチーフ（†・✡等）は一切使わない**
- **糸目**。昼は糸目、夜/核心の場面で目が開く
- **目の隈**。物語の進行とケアの結果で増減する
- 表情差分は **「感情セット（喜怒哀楽）＋ 目の開度（糸目/半目）＋ 隈の濃さ」** で設計する
  （2026-07-13 更新。詳細は後掲「表情設計を『感情セット＋目の開度＋隈』に再構成」参照）
- **背中の衣服に横一線の切れ目**。通常は意匠に見えるが、夕方の祈りの時にそこから翼が出る。冒頭のハプニングで判明する
- 髪は長め

**理由**
- 糸目と隈は一見両立しないが、**「昼＝糸目／夜＝開眼」の対比構造にすることで、作品の核である昼夜のギャップそのものを表情システムに載せられる**
- 糸目のまま隈が隠れ、開眼した瞬間に疲弊が露わになる、という演出が成立する
- 宗教モチーフを使わないことで、DLsiteの一覧面で「よくある堕天使モノ」に埋没するのを避ける
- 背中の切れ目は「普段は服の意匠に見え、後から意味が判明する」伏線として1枚絵に忍ばせられる
- 髪が長い理由：①梳くシチュエーションが作れる ②翼が出る背中を髪が隠す/かき上げる演出が生まれる

**却下した案**
- **輪（halo）・翼を聖性の記号として前面に出す**：却下。他の天使モノに埋没する。この作品の天使は「万能に救済する天使」ではなく「疲弊した天使」であり、そこが差別化点
- **喜怒哀楽を"大きな表情"（目を見開く等）で切る**：却下。この天使は本気で怒らず、糸目が基本。
  感情は糸目/半目を基盤に口・眉・頬で載せ、開眼は核心の特別カットに限定する（2026-07-13 更新。後掲項参照）

**未確定**
- 髪色
- 差し色

# 2026-07-13｜イラスト外注の方針

**決定**
- 発注先は**1人**（R-18まで一貫して依頼する）
- 探索軸は**線と色**：①線に勢いとかすれがあるか ②限定パレットを使えるか ③日常の温度と崩し/狂気の両方を描いた実績があるか
- 発注前に**天使様のビジュアル記号を作者側が言語化して渡す**

**理由**
- R-18を受ける絵師は全年齢のキービジュも描けるが、逆は成立しない。1人に統一しておく方が選択肢が残る
- 参照している作家性（線の勢い＋限定パレット）は、**記号を渡すと爆発するタイプ**であり、「かわいいシスターを描いて」と丸投げすると弱い成果物になる

**却下した案**
- **天使様用とSteam組（他3本）で絵師を分ける**：一旦却下。当初は「参照作家＝狂気/ダーク軸だからいやしけいには使えない」と判断したが、追加の参考画像で**同じ作家性が日常の温度も描けること**が判明したため、軸を1本に統合した

**契約上の必須項目**
- 著作権譲渡（27条・28条を含む）
- **著作者人格権不行使特約**（Steamカプセルやサンプル画像のトリミング・調整に必須。人格権は法律上譲渡できないため、特約がないと改変が差し止められうる）
- 二次利用範囲の明記（ストア・SNS・広告・動画サムネ・出展・グッズ・続編）
- AI学習用途への提供禁止

# 2026-07-13｜開発ワークフローの分離

**決定**
- **仕様の相談・決定はチャット側**（Claude Desktop/アプリ）で行う
- **実装はClaude Code**で行う
- Claude Codeは **1タスク1セッション**。完了したら `/clear` する
- Claude Codeが仕様変更の必要を感じたら、**勝手に決めずに停止して論点として提示する**
- ローカルの `docs/` 配下のmdが正、Notionはミラー

**理由**
- 長時間セッションの後半で、初期に決めた前提がコンテキストから押し出され、精度が静かに劣化する現象が実際に発生した
- サブエージェントは親の文脈を持たないため、タスク指示文が自己完結していないと機能しない
- 「1機能ずつ、動いたらコミット」という既存の開発規約が、そのままセッションの区切り単位として最適

**却下した案**
- **ChatGPT Work + n8n + Notion で要件定義と実装を分業する**：却下。①コスト削減の前提が成立しない（サブスク内で完結する作業を有料APIに逃がす形になる）②n8nの保守コストがソロ開発には重い ③別モデル系を挟むと文脈の損失がむしろ増える
- **Claude Code に Notion MCP で毎回仕様を読ませる**：却下寄り。トークン消費が大きい。リポジトリ内のmdを正とし、Notionは人間とチャット側が読むミラーとする

**モデル選択**
- 日常＝Sonnet 5、難所＝Opus 4.8。**Fable 5は原則使わない**（2026-07-13よりサブスク定額枠から外れ、完全従量課金に移行したため）

# 2026-07-13｜表情設計を「感情セット＋目の開度＋隈」に再構成

> 上記「キャラクター記号の確定」の表情軸を更新する項。旧方針「目の開度×隈のみ／喜怒哀楽は却下」を差し替える。

**決定**
- 表情は **感情セット（喜怒哀楽）を採用**する。ただし糸目・半目をベースに、**口・眉・頬**で感情を出す（大きく目を見開く方向には振らない）。
  - 笑顔（糸目/半目・口元笑顔）
  - 大笑顔（大きく口を開く・笑い泣きの涙マーク案あり）
  - 怒り（糸目・頬膨らませ ＝ 本気の怒りではない）
  - 悲しみ（糸目/半目〔本気の悲しみのときのみ半目〕・口元への字・眉にしわ）
  - 驚き（糸目/半目・口元 o の字）
  - ＋ 平常
- 表情は **3レイヤー構成**：①感情セット（口/眉/頬/涙）②目の開度（糸目/半目＝補助軸）③隈の濃さ（状態軸）
- 立ち絵は **レイヤー分離（PSD等）で納品・合成**し、組み合わせ爆発を避ける（＝発注枚数の土台）。
- **開眼（大きく目を開く）は日常表情から外す**。**正体開示・夜ケア核心の「特別カット」としてのみ残す**
  （最終確定は SESSION_STATE の未確定項目「開眼の扱い」で行う）。

**理由**
- 当初は「表情＝目の開度×隈のみ（喜怒哀楽ではない）」としたが、作者の作画イメージ（各感情の口/眉/頬の具体）が明確で、糸目キャラの抑制された感情表現とも両立する。
- 糸目/半目を基盤に感情を載せることで、旧却下理由「糸目キャラでは表情の幅が死ぬ」を回避しつつ喜怒哀楽を持てる。
- 開眼を"怒り"ではなく"心を許す/求める核心"に限定することで、商品の核「昼＝糸目 ↔ 夜/核心＝開眼」のギャップを一枚看板として温存できる（作者が嫌うのは「怒りの開眼」で、この作品の核心開眼は用途が別）。

**却下した案 / 変更点**
- 旧方針「表情を喜怒哀楽で切るのは却下・目の開度×隈のみ」→ **更新**。糸目/半目を基盤に喜怒哀楽をレイヤーで載せる形へ統合。
- **組み合わせをフルCGで描く**：却下。枚数が乗数的に増える。レイヤー合成にする。
- **開眼を日常表情に使う**：不使用（このキャラは本気で怒らない）。ただし核心の特別カットは残す（下記 未確定）。

**根拠・先行事例**
- 作者提示の感情別パーツ定義（上記）。
- ノベルゲーム/立ち絵差分の一般的手法（目・口・眉を別レイヤーで持ち、実行時に合成）。

**未確定（SESSION_STATE 参照）**
- **開眼の扱い**：核心の特別カットとして残す（推奨）か、完全にナシにするか。完全ナシは確定設定「夜/核心で目が開く」の撤回になる。
- **隈の濃さと数値の結線**：既存 `angelFatigue` に結線するか、専用 `kumaLevel`(0–2) を新設するか。
- **表情段階数**：目（糸目/半目〔＋開眼は上記次第〕）、隈（2段 or 3段。推奨3段）。発注枚数の確定に直結。
