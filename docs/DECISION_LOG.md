## 2026-07-13 セッション

### D-01. 全年齢/R-18 差し替えアーキテクチャの採用

- **決定**: 同一データ構造から全年齢版とR-18版を出力できる差し替え層を導入。
  `content-config.js`（`mode: 'all_ages' | 'r18'` の唯一の切替箇所）、
  `asset-resolver.js`（`AssetResolver`。normal/adult 参照を解決）を新設。
  テキストは `text_normal` / `text_adult`、CGは `{scene_id}_normal` / `{scene_id}_adult`。
- **理由**: 将来のUnity移植で解決層をC#クラスへそのまま写せるよう、DOM非依存の純ロジックに閉じ込めたかった。コードにコンテンツを書かない原則を守るため。
- **却下した案**:
  - *モード分岐をコード各所に散らす* → 変更点が増え移植性が落ちる。切替は1箇所に集約。
- **根拠**: プロジェクト指示書「アセットとロジックの完全分離」「AssetResolver相当の解決層」。

### D-02. レガシー互換（`text` = `text_normal`）＋段階移行

- **決定**: 従来の `text` キーは `text_normal` と同義として扱い、差分を入れるエントリだけ `text_normal`/`text_adult` へ移行する。既存データは一括書き換えしない。
- **理由**: 既存の全エントリを無変更で動かしたまま、必要な箇所だけ移行できる。事故が入りにくい。
- **却下した案**: *全エントリを一括で `text_normal` へリネーム* → 大規模変更で差分が膨らみリスク大。段階移行を選択。

### D-03. フォールバック規則（差し込み前でも常に動く）

- **決定**: `r18` で `text_adult` が未定義、または `[TODO:` で始まるプレースホルダなら `text_normal` に自動フォールバック。CGも `cgRegistry` に `{id}_adult` が無ければ `{id}_normal`。
- **理由**: R-18本文・CGが未差し込みでも常にゲームが動く状態を保つため。
- **根拠**: 指示書「adult側が未定義なら normal に自動フォールバック」。

### D-04. AIはR-18の中身を書かない（プレースホルダのみ）

- **決定**: R-18テキスト・CGの具体は作者専管。データ整備では `[TODO:作者差し込み]` のみ置く。
- **理由**: 役割分担（AIの担当外）。品質と作家性を作者に残す。
- **根拠**: 指示書「コンテンツ分担」。

### D-05. git安全性 — センシティブ素材はコミットさせない

- **決定**: `.gitignore` で adult/r18 ディレクトリ、`**/*_adult.*`、制作元データ（`.psd`/`.clip` 等）、
  `night-care.adult.csv` / `*.adult.csv` / `night-care-data.adult.js` を除外。実CG・実ボイスは
  git非管理とし、ローカル / Unity アセット / DLsite配信で管理。
- **理由**: git履歴は後から消せず、push後は特に取り返しがつかない。DLsite頒布物・R-18素材の流出経路を作らない。
- **却下した案**: *実素材もgitで管理* → 履歴不可逆＋規約リスク＋バイナリ肥大で却下。
- **根拠**: git履歴の不可逆性。GitHub Acceptable Use（性的に露骨なコンテンツ制限）。

### D-06. 夜ケアデータのCSV化

- **決定**: 夜ケア本文を `night-care.csv`（表計算で編集）→ `tools/build-nightcare.js` で
  `night-care-data.js` を生成する方式に変更。`night-care-data.js` は自動生成物（手編集禁止）。
- **理由**: 型が決まっている夜パートは表で編集できる。作者が使い慣れた表計算で一括編集でき、Unityも同CSVを流用できる（移植で無駄にならない）。
- **却下した案**:
  - *アプリ内エディタを実装* → HTML固有の作り込みでUnity移植時に捨てる。労力大。却下。
  - *実行時に `fetch` でCSV読込* → `file://` でブラウザが弾く。生成方式なら実行時ローダ不要で回避。
- **根拠**: 「index.htmlを開くだけで動く」制約の維持。CSV/TSVはUnity（ScriptableObject/Addressables）でも一般的。RFC4180準拠パーサ。

### D-07. 実R-18本文のadult別CSV分離（方針のみ・実装は将来）

- **決定**: 実R-18本文を入れる段階で、adult列をgitignore対象の別CSV（`night-care.adult.csv`）へ分離し、idでマージする。`.gitignore` は先行して除外設定済み。
- **理由**: D-05の延長。全年齢CSVは追跡、adult本文は非追跡に分ける。
- **状態**: 実装は保留（実本文を書く段階で着手）。

### D-08. 開発体制 — Opus設計/レビュー・Sonnet実装・レビューゲートあり

- **決定**: 仕様確定・設計・レビューはOpus、実装はSonnetサブエージェント。Sonnetは
  「実装＋動作確認」まで行い、**commit/push前に必ずOpusが差分レビュー**する。
- **理由**: 個人開発の速度と品質の両立。サブエージェントは毎回まっさらな文脈で走るため「実装前に仕様を確定」が構造的に強制される。R-18のgit事故を一段止められる。
- **却下した案**: *Sonnetにpushまで直接任せる* → レビュー前に変な差分が本流に乗る／git事故のリスク。レビューゲートありを選択。

### D-09. 販売方針 — R-18版のみ制作

- **決定**: R-18版のみ制作、DLsite先行。Steamは成人向け決済リスクのため対象外。全年齢版は当面作らない（必要になれば再判断）。技術構造としての「全年齢base＋adult overlay」は維持。
- **理由**: 作家性の主題がR-18側にあり、そこに集中する。技術baseは維持することでR-18ビルドがその上に載り無駄にならない。
- **却下した案**: *まず全年齢版を出す（旧CONCEPT合言葉）* → 方針転換。ただし全年齢**base**は技術構造として残す。
- **状態**: 正本CONCEPT.md / Notion合言葉「まず全年齢基盤」への反映は未実施（要更新）。

### D-10. キャラクター記号（確定）

- **決定**: シスター服ベース。実在宗教モチーフ（†・✡ 等）は不使用。糸目（昼）／夜・核心で目が開く。
  目の隈（進行・ケア結果で増減）。背中の横一線の切れ目→夕方の祈りで翼。翼＝白・先端黒。髪は長め。
- **理由**: 「目の開度 × 隈の濃さ」を表情の主軸に据える独自性。糸目→開眼のギャップが商品の核。
- **却下→撤回した案**: *魔法陣を世界観から落とす*（宗教モチーフ不使用と衝突するため一度提案）
  → **却下**。魔法陣は「既存宗教と重ねない、独自宗教観のアイコン」として**残す**。線引きは
  「実在宗教の記号は使わない／独自宗教のアイコンは使う」。
- **根拠**: Notion正本「天使様」（翼＝ほぼ白・先端黒、慢性疲労→夜ケア導線、過去に恐れられた）。

### D-13. 表情システムを「レイヤー合成」で持つ（見積もりの土台）

- **決定**: 立ち絵の表情はフルCGの組み合わせで描かず、ベース立ち絵＋パーツレイヤー（目/口/眉/頬/隈 等）を合成する。発注は**PSD等のレイヤー分離納品**を必須条件にする。
- **理由**: 組み合わせ爆発を避け発注枚数を抑える。目3×隈3を9枚描くのではなく差分6枚で9通りを出せる。
- **却下した案**: *組み合わせをフルCGで描く* → 枚数が乗数的に増える。却下。
- **根拠**: ノベルゲーム/立ち絵差分の一般的手法（目・口・眉を別レイヤーで持つ）。
- **状態**: 段階数は未確定（SESSION_STATE 未確定項目参照）。

### D-14. 表情の設計方針を「感情セット＋目の開度＋隈」に再構成

- **決定**: 当初「表情＝目の開度×隈の2軸（喜怒哀楽ではない）」としていたが、作者意向で
  **喜怒哀楽も入れる**方向に再構成。感情（笑顔/大笑顔/怒り/悲しみ/驚き）は**糸目・半目**ベースで表現し、
  目の開度は補助軸、隈は状態軸とする3レイヤー構成。
- **理由**: 作者の作画イメージ（各感情の目/口/眉/頬の指定）が明確で、糸目キャラの抑制された感情表現とも整合。
- **却下→再検討中の点**: 「開眼（大きく見開く）」は日常表情としては不要（このキャラは本気で怒らない）。
  ただし確定設定「夜／核心で目が開く」と衝突するため、**開眼を"感情"から切り離し、正体開示・
  夜ケア核心の"特別カット"としてのみ残す**案を提示。最終判断は未確定（SESSION_STATE参照）。
- **根拠**: 作者提示の感情別パーツ定義（笑=糸目/半目・口元笑顔、大笑=大きく口＋涙マーク案、
  怒=糸目・頬膨らませ、悲=糸目/半目・への字・眉しわ、驚=糸目/半目・o口）。
